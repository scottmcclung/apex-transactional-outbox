# Baseline, before any fixes

- **Date:** 2026-11-16
- **Code:** `force-app` from `main` at `aad6e5f`
- **Org:** scratch org, Developer edition
- **Setup:** one subscription per message, max attempts 3, retry backoff 0

These are scratch org figures. They are for comparing versions and do not predict production.

| 10 | 2 | 2 | 29 | 1 | 2 | 19 | 13,492 | 0 / 0 |
| 100 | 2 | 2 | 52 | 1 | 2 | 27 | 73,882 | 1 / 1 |

- Queries are flat at every size.
- One relay job at every size, when nothing fails and nothing is called.
- Publishing 5,000 messages with one subscription each uses all 10,000 DML rows a transaction allows.
- Run CPU grows faster than the number of outboxes. The cause has not been found.

## With HTTP callouts

| Scenario | Command | Result |
|---|---|---|
| 120 messages, fast endpoint | `bench.js bench_http_ok 120 150` | All delivered once. 2 relay jobs, the first failed with `Too many callouts: 101`. Delay median 8 s, p95 14 s |
| 3 messages, endpoint returns 503 | `bench.js bench_http_503 3 90` | All dead-lettered after 3 attempts. 3 relay jobs |
| 3 messages, endpoint does not answer | `bench.js bench_http_down 3 90` | All dead-lettered after 3 attempts. 3 relay jobs |
| 16 messages, endpoint takes 8 s | `bench.js bench_http_slow 16 330` | All delivered. One attempt failed with `Exceeded maximum time allotted for callout (120000 ms)` and succeeded on retry |
| 50 messages, endpoint takes 8 s | `bench.js bench_http_slow 50 520` | 45 delivered, 5 dead-lettered without being sent. 3 relay jobs |

In the 50 message run, each relay run delivered 15 and then failed every remaining outbox with the callout time error. Each failure counted as an attempt.

## Payload size

Payload of 131,072 characters, the most the field holds. Commands: `node heap.js 131072 200 20,40,80,100,200` and `node heap.js 131072 1000 400,700,1000`

| Due at once | Long text loaded | Result |
|---|---|---|
| 20 | 2.6 MB | Completed |
| 40 | 5.3 MB | Completed |
| 80 | 10.5 MB | Completed |
| 100 | 13.2 MB | Completed, although over the 12 MB heap limit |
| 200 | 26.4 MB | Job failed with `Apex heap size too large` after sending. All 200 delivered and saved by the finalizer |
| 400 | about 52 MB | Job failed at the load with `Query of LOB fields caused heap usage to exceed limit.` Nothing attempted, nothing saved, no next run |
| 700 | about 92 MB | Same as 400 |
| 1,000 | about 131 MB | Same as 400 |

A full payload costs about 132 KB of heap, one byte per character.

## Daily asynchronous executions

Ten relay runs, each followed by its finalizer, used 7 of the org's daily asynchronous Apex executions. A finalizer is not counted as a second execution.

## Faults reproduced the same day

`malformed-config` and `missing-subscription` each produced 6 failed relay jobs and left a healthy message undelivered. `missing-definition` and `bad-action-class` each produced 1 failed job and delivered nothing. `action-called-with-null` showed an action called with null. `cleanup` showed the query selecting an outbox with a future TTL and the real cleanup throwing. Details are on the repository's issues.
